# JARVIS 실테스트 영상 시나리오

다른 노트북에서 Userspace를 실행하고 SaaS Controller에 연결한 뒤, 아래 순서로 촬영한다. 각 장면에서 화면과 Userspace 액션 피드를 함께 보이게 한다.

## 사전 준비

1. Userspace의 `config.json`에서 테스트할 capability만 활성화한다.
2. `.env`의 `AUTH_API_BASE`, `OLLAMA_BASE_URL`에 Controller 주소를 넣는다.
3. macOS라면 Accessibility 권한을 허용한다.
4. Controller의 `/health`가 healthy인지 확인한다.
5. 브라우저를 열고 로그인 상태가 필요한 사이트는 미리 로그인한다.

## 촬영 순서

### 1. 일반 대화와 액션 분리

요청: `오늘 서울 날씨가 어때?`

기대 결과: 일반 답변만 생성되고 `action_dispatch`가 발생하지 않는다.

요청: `브라우저에서 서울 날씨 검색해줘`

기대 결과: `browser.search` 또는 `open_url`이 큐에 들어가고 브라우저가 검색 결과를 연다.

### 2. 앱 열기와 텍스트 입력

요청: `메모장을 열고 테스트 영상 촬영 중이라고 입력해줘`

기대 결과: 등록된 정확한 앱 이름으로 앱을 열고 `keyboard_type`을 실행한다. 앱 이름이 등록되어 있지 않으면 실행하지 않고 이유를 표시한다.

### 3. 브라우저 검색 후 결과 선택

요청: `네이버에서 JARVIS 검색해서 첫 번째 결과를 열어줘`

기대 결과: 검색 → 첫 번째 결과 선택이 순서대로 실행된다. 각 단계에 `queued → in_progress → completed`가 표시된다.

### 4. 현재 페이지 요소 조작

요청: `현재 페이지에서 검색창을 찾아 JARVIS Userspace를 입력해줘`

기대 결과: DOM 추출 후 입력 요소를 찾아 `type_element`를 실행한다. 요소를 찾지 못하면 후속 입력을 만들지 않고 실패 사유를 표시한다.

### 5. 사용자 확인이 필요한 액션

요청: `터미널에서 현재 폴더 파일 목록을 보여줘`

기대 결과: 확인 UI가 먼저 나타나고, 승인하면 실행된다. 거부하거나 시간 초과하면 `rejected` 또는 `timeout`과 사유가 사용자에게 표시된다.

### 6. 정책으로 차단된 액션

사전 설정: `mouse_click` 또는 `terminal` capability를 끈다.

요청: `화면 가운데를 클릭해줘`

기대 결과: 노트북에서 아무 조작도 일어나지 않고 `policy_disabled` 실패가 액션 피드와 최종 응답에 표시된다.

### 7. 템플릿이 없는 액션 회귀 테스트

요청: `노트북에서 지원하지 않는 작업을 자동으로 처리해줘`

기대 결과: 임의 액션을 만들어 실행하지 않는다. `액션 실행 불가` 단계와 구체적인 실패 사유가 표시되고 조용히 일반 대화로 끝나지 않는다.

### 8. 핸들러가 없는 액션 회귀 테스트

개발 설정에서 서버가 보내는 액션 타입을 Userspace에 등록하지 않은 상태로 만든다.

요청: 해당 액션을 실행한다.

기대 결과: `no handler registered` 실패가 Controller로 반환되고, 같은 요청의 후속 액션은 실행되지 않는다.

### 9. 복합 액션 중간 실패

요청: `브라우저에서 검색하고 첫 번째 결과를 연 다음 지원하지 않는 후속 작업을 해줘`

기대 결과: 앞 단계 결과와 실패한 단계가 각각 표시되고, 실패 이후의 후속 액션은 차단된다. 최종 응답에는 완료 개수와 첫 오류가 함께 나온다.

### 10. 화면 스트림 상태 확인

사전 설정: `screen_stream`을 활성화한다.

동작: 화면 스트림을 시작하고 중지한다.

기대 결과: 프레임 전송 상태와 중지 결과를 확인한다. 현재 버전에서는 프레임이 AI 추론 루프에 자동 연결되지 않으므로, 화면을 보고 클릭하는 시나리오의 근거로 사용하지 않는다.

## 촬영 체크포인트

- 음성 또는 텍스트 요청이 화면에 남아 있는가
- `action_intent`, `action_dispatch`, `action_result` 순서가 보이는가
- 성공·거부·시간 초과·정책 차단·핸들러 없음이 구분되는가
- 실패 후 후속 액션이 실행되지 않는가
- 최종 응답에 실행 결과 또는 실패 이유가 표시되는가
